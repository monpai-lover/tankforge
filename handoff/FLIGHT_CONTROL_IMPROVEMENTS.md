# 飞控改进

本轮落实了[GitHub 飞控对照报告](FLIGHT_CONTROL_COMPARISON.md)中的输入顺序、双向包线、遥测，以及触控／标准手柄接入。参考项目的控制结构用于这套游戏已有的 C/WASM 气动模型，没有照搬 Nuclear Option 的操纵增益。

## 输入和操控

鼠标世界准星先更新，再执行本次 120 Hz 物理步。测试记录实际 `step()` 的目标向量，确认同一次游戏更新的第一个物理步已经收到新意图；这消除了调用顺序造成的一帧等待，不代表测量了屏幕端到端延迟。

飞机触控复用现有按钮，并随上下机切换标签与动作。摇杆上／下增减油门、左／右滚转；拖动屏幕移动准星；按钮支持全部开火、机炮、视角、起落架、襟翼、刹车、自由观察和内构。射击仍经过已有枪械／弹药接受路径。每个触点单独认领，松手、取消捕获、失焦均清理输入；触控释放不会取消另一来源仍按住的射击或自由观察。

标准手柄采用固定映射：左杆纵向俯仰、横向滚转，右杆横向方向舵，RT／LT 增减油门，A 全部开火，B 机炮。死区 0.12，余下区间重新映射，混合 35% 三次曲线。只接受浏览器 `mapping="standard"` 的设备；失焦、断开和切换设备后需先回中并松开扳机／射击键，才重新接受输入。键盘持有的轴优先，触控滚转优先于手柄滚转。本轮没有加入任意 USB 飞行杆的校准或轴重映射界面。

襟翼有“收起／作战／起飞”三档，F 与触控襟翼按钮均按该顺序循环；HUD 和按钮显示所选档位。跑道初始为起飞档，空中出生为收起。核心目标伸出比例为 0／0.25／0.5，现有襟翼模型约对应 0°／10°／20°；实际伸出量仍以每秒 0.65 的速率平滑变化，升力、阻力和模型动作均读取同一个接受状态。诊断 CSV schema 2 同时记录档位、目标及实际比例。外部脚本旧布尔值 `true/false` 分别映为起飞／收起。

## 双向包线与核心

核心版本升为 203，保留现有 `configure`／`step` ABI 和 80 个遥测位置，新增 `configure_envelope(maxG,minG,maxAoA,minAoA)`。正 G 采用现有机型配置，默认负 G 为 −3；迎角默认依据该机型失速角和襟翼状态，并按动压、质量、翼面积、升力斜率及受损翼面积收紧 G 对应的迎角门槛。默认值是游戏模型的保守护栏，并非历史认证包线；机型可通过 `minGLimit`、`maxAoA`、`minAoA` 覆盖。

两套教官、手动接管、正向和负向操纵共用一个有阻尼的控制出口。门控、恢复命令和最终舵面需求使用本机力矩关系，不会在反向操纵时互相取消必要的制动。保护修改的是控制命令，未新增速度、姿态或物理载荷的硬裁剪。保护或教官任一关闭，就恢复原有未保护的操纵语义。平飞配平的升力斜率也由固定 4.5 改为本机 `af_cla`。

低可用升力时，关闭迎角门控后的基线逐渐转为零舵自然稳定，而不是继续跟随抬升的航迹。这样可以提前保留降头恢复能力，避免持续满拉耗尽速度后才尝试恢复；它没有改变发动机、升阻力或飞机状态。

原生索引 77／78 为负迎角／负 G 门控，79 为负 G 限；已有索引保持不变。[构建说明](flight/README.md)给出了可复现的编译命令，构建脚本同步独立 WASM、base64 和页面嵌入，`--check` 会重新编译并逐字节检查三处一致。

## 诊断与复现

飞机出击后按 F10 或点击“飛控診斷”。默认关闭，关闭时不采样；开启后 30 Hz 记录，最多 1,800 行，显示指令／实际角速度、迎角、G 和双向门控，并可导出 CSV。角速度符号、弹道偏置后的输入目标和重生分段见[诊断说明](FLIGHT_DIAGNOSTICS.md)。

实际场景测量使用 `tests/flight_envelope_scenarios.mjs`，成对比较使用 `tests/flight_envelope_report.mjs`。测量脚本报告超限幅度、持续时间和末段波动；“有限数值、未坠毁”不会被当作保护达标。

```sh
node --test handoff/tests/*.test.mjs
node handoff/tests/flight_envelope_scenarios.mjs --types all --json /tmp/flight-envelope.json
node handoff/tests/flight_control_probe.mjs
```

真实游戏浏览器场景分别位于 `tests/flight_input_browser.js`、`tests/flight_diagnostics_browser.js` 和 `tests/flight_smoke_browser.js`，覆盖实际输入事件、物理步、弹药消耗、CSV 和起飞／目标捕获。

`tests/flight_flaps_browser.js` 另外验证了真实 F 键与触控按钮各一轮三档切换、跑道／空中默认档、旧布尔脚本、实际原生标志及平滑动作。P-51 两侧实测模型偏角为 0°／10.027°／20.054°，HUD 和按钮显示对应档位，浏览器错误为零。

## 最终核心的测量

旧 202 源码与新 203 用同一 Zig 0.13 编译器成对构建。正式交付核心为 22,148 字节，SHA256 `7d6a78b1a62ce63240b1fc531d32afe80c1da81d6e3c6e5005bfa20da4576863`；源码重编译、独立文件、base64 和页面嵌入逐字节一致。全部 92 项 Node 回归通过，其中包线文件执行了 15 组核心行为断言，襟翼文件执行了 13 组原生行为检查。

17 型、541 个场景均完成规定步数、遥测有限、无坠毁，含 102 个通过实际滚转进入倒飞的准备过程。529 个开启保护的场景中，最大正 G 超限为 0.02535 G，最大负 G 超限为 0.02443 G。12 个关闭保护或教官的对照场景，记录的物理统计与基线六位小数一致。这些是指定场景的结果，不能由“没有坠毁”推导任意情况下都不会超限。

| 场景 | 旧核心 | 新核心 |
| --- | ---: | ---: |
| NF-01，3000 m、140 m/s，满推杆 2 s，最低 G | −7.701 | −1.920 |
| 同条件满拉杆 2 s，最高 G（配置正限 6.5） | 9.096 | 5.587 |
| A6M2，6000 m、70 m/s，连续满拉 60 s，最大迎角 | 24.56° | 24.09° |

NF-01 在 6000 m、220 m/s 先推 5 s 再拉 5 s，最终最低／最高 G 为 −2.158／6.074，末 3 秒围绕平均值的 RMS 波动为 0.03575 G；相反顺序也通过回归。该检查会捕捉高速反向时的持续泵振。A6M2 的 60 秒回归用于防止低速满拉出现新的深度失速退化。

跟踪使用“误差连续保持在 3° 内至少 1 秒的起始时刻”，避免把瞬间擦入准星当作捕获。6000 m、140 m/s 的 F-104 从 11.275 s 到 11.733 s，约慢 4%；其余 16 型不超过 0.033 s 的增加或有所改善。所有机型末 10 秒 RMS 跟踪误差均不超过 0.044°。这些测量没有在 Nuclear Option 的同一气动模型上运行外部教官，不能据此宣称跨游戏性能排名。

仍存在软保护的实际限制：A6M2 低速持续满拉可超过配置迎角约 7.93°，受损 F-104 低速可超过负迎角限约 7.03°；舵效不足、极端初始状态与持续失速工况不能保证恢复。本轮也未替换已有聚合气动、通用发动机曲线和简化地面接触。分翼面失速、下洗／桨流、独立轮胎接触及完整能量管理仍需单独建模与验收。

最终场景 JSON、成对分析、短测及原始基线保存在本机 `tests/out/flight-control-improvements/`。旧对照报告的数据保留在原目录，没有用新数值覆盖。

正式页面的 Chromium/SwiftShader 验收通过：NF-01、P-51D、F-104G、Mirage IIIE 都实际起飞并在 30 秒内捕获 60°目标，末端误差分别为 0.259°、0.240°、0.223°、0.061°。真实 DOM 鼠标／触控事件到 WASM 和弹药消耗均已检查；标准手柄使用 Gamepad API 合成输入检查断开、失焦与回中重启，未连接实体硬件。诊断实际下载的 CSV 为 98 行、54 列，包含真实键盘输入、核心版本及双向门控。浏览器运行错误为零；诊断关闭后记录不再增长。测试使用五种原始战车定义和原始表面目录，低画质，仅降低背景云成本。完整交付 HTML 已重建，其脚本尾部与当前源码逐字节一致。
