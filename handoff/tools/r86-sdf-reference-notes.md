# SDF 求交参考核查与独立诊断

## 结论与接入范围

用户建议的 `t = 1.0` 与 `abs(d) < 0.01` 都有用，但合起来仍不是完整求交器。需要同时处理正向步进、有效射线区间、未命中、非有限值和步数耗尽。

本包附带自行编写的 `r86_sdf_intersection.mjs` 与 `../tests/r86-sdf-intersection.test.mjs`，用于数学诊断和今后的实验。它们没有接入游戏帧循环、材质、云密度、三角面碰撞或载具命中盒，也没有导入参考场景。

参考输入是用户附件「已粘贴的文本.txt」，SHA-256：

```text
a98fc8d0ffc5764f0ec982990a6e4795c54aefc8d0470857c2fc24e9c8471854
```

该份输入实际的求交函数在第 192–200 行：第 193 行从 3 开始，第 196 行的提前返回被注释，第 197 行按带符号值累加距离。用户所说的约 200/203 行，应按这个实际函数定位。附件只作只读核查；作者与再分发许可尚未确认，完整示例场景没有复制到产品或源码包。这里的工具、测试与说明都是独立编写的。

## 为什么两处改动有帮助，以及它们的边界

1. **从 3 改为 1：恢复原先跳过的一段射线。** 例如球心在射线前方 2、半径 0.2，正面交点是 1.8。从 3 起步已越过整个球；从 1 起步能找到它。但是 1 以内的物体仍然会被裁掉。近端应由相机和查询目的决定，不是固定的通用常数。
2. **用绝对残差判断命中：避免把“深处内部”当表面。** 对真正的 SDF，负数表示实体内部。例如在半径 2 的球内，距离为 -1 时，`d < 0.01` 成立，但采样点离球面还有 1；应检查残差的绝对值。
3. **只改命中条件，仍会向后走。** 保留 `t += d` 时，内部的负值会减小 t，甚至走到近端或相机后方。要寻找正向出口，步长必须非负。附带工具使用绝对残差除以已声明的 Lipschitz 上界，再乘不大于 1 的安全系数。
4. **步数用尽不是命中。** 原示例即使没有收敛也返回最后的位置，调用者随后计算法线与颜色，容易把未命中伪装成表面。诊断工具只有 `hit === true` 才提供交点；其余情况的 `point` 都是 `null`。

示例中的“Return/Break doesn't work”注释不能证明 GLSL 控制流或驱动有问题：该行本身被注释，近端和内部符号也会造成看似异常的结果。应先检查这些可重现的数学问题，再调查编译器或驱动。

另一个独立细节是：示例场景函数会写入每个物体的全局距离缓存，而法线差分又会在偏移位置多次调用场景函数；随后材质选择读到的可能是最后一个差分点的缓存。若继续诊断这个示例，应将距离与材质身份一起返回，或在真正命中点重算材质查询，避免依赖这种隐藏调用顺序。游戏已有的材质绑定不应改成这套示例缓存方式。

## 步进成立的前提

真正的有符号距离场满足单位 Lipschitz 条件，绝对距离可以提供到最近零面的安全步长。对一般隐函数，若已知 `|f(a)-f(b)| <= L |a-b|`，则可用 `abs(f)/L` 作为前进距离的下界；L 必须是有效上界。

附件中的波动平面和高频帘幕进行了非线性位移，它们不能直接当作已经证明的单位 SDF。以单位水平面加振幅 0.1、频率 3 的两个正弦乘积为例，每个水平偏导的绝对值至多 0.3；`sqrt(1 + 0.3² + 0.3²)` 是一个保守梯度上界。高频帘幕需要另外分析其变换的导数。把所有步长随意乘 0.9 并不构成一般的防穿越保证。

工具允许传入 `lipschitz`；它不会猜测任意回调的正确上界。`epsilon` 衡量的是回调值的残差。只有回调是真正以米为单位的 SDF 时，0.01 才能直接解释为离表面约 1 厘米；对于一般隐函数，它只是数值容差。错误的场、过小的 L、薄于容差的特征及浮点误差，仍可能造成漏检或提前收敛。

## 独立工具的契约

```js
import {marchSdf} from './r86_sdf_intersection.mjs';

const result = marchSdf(
  p => Math.hypot(p[0], p[1], p[2] - 2) - 0.2,
  [0, 0, 0], [0, 0, 1],
  {near: 1, far: 10, epsilon: 0.01, maxSteps: 128, safety: 0.9, lipschitz: 1},
);
```

- 自动归一化方向；t、near、far 表示沿射线的实际长度。
- 在闭区间 `[near, far]` 内采样；far 端点也可能是有效命中。
- 若起点在内部，寻找区间内的正向出口，不把任意负值直接判为命中。
- 返回 `hit`、`reason`、`t`、`point`、`distance`、`steps` 和 `startedInside`。steps 是实际场函数求值次数；t 是结束时的射线参数。步数用尽时它对应最后一次已求值采样；坐标非有限时不会调用场函数。
- 非命中原因包括 `far`、`step_limit`、`non_finite_distance`、`non_finite_position` 和 `stalled`。回调自身抛出的错误直接传播。
- 配置与射线先验证；步数上限为 65536，默认 128；不会以无限循环补偿不收敛。输入向量与配置不被修改。
- 此工具按诊断用途分配采样数组，没有宣称满足游戏热循环的零分配要求。

## 对游戏与云层的实际建议

保留现有渲染三角面、已登记装甲、原生伤害、PBR、天空和阴影的职责。不要把示例的球、盒子、帘幕或光照场景注入游戏，也不要对所有材质额外执行完整 SDF 场景遍历。

可以借鉴的只是一般原理：

- **软阴影：** 沿光线方向累计有界遮蔽。点光源的方向应来自“光源位置减采样点”，不能一般性地用光源相对世界原点的方向。太阳光继续使用现有方向光定义。
- **AO：** 表面法线方向的距离采样可估计局部净空；这不是云的光学厚度。云层应沿已有密度场积分消光与散射，透射率采用光学厚度模型，而不是把密度当 SDF 距离来跳步。
- **间接光：** 保留现有环境光与 PBR 能量关系。示例按邻近物体颜色加权的“假 GI”不能直接视作物理全局光照，也不值得为此对每个材质增加昂贵场景查询。

其他云参考中明确禁止产品使用或分发的实现，不应复制、改名或移植。云改进应由其现有密度与合成所有者独立实现，并核查各参考各自的许可；这份数学诊断不放宽任何参考代码的许可限制。
