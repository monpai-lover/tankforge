# AAM realism design and implementation plan

Goal: preserve the existing 33 store entries and authoritative hit/damage path while removing demonstrated flight and postlaunch seeker advantages. These are public-source physical principles and declared game approximations, not certified real missile performance envelopes.

The aircraft AAM path is separate from the Rust `missile` crate's ATGM path: local play uses `stepOrdnance`/`missileGuide` in the canonical handoff bundle; native multiplayer uses `frontline_air_missiles.rs` and `frontline_sim.rs`. Existing per-store mass, span, burn, thrust, lifespan, G limit, rear aspect and seeker track-rate values remain the inputs.

Use one matching JS/Rust budget. Aerodynamic control authority scales with dynamic pressure using the browser's existing 60,000 Pa reference. Add a maneuver drag term based on accepted lateral acceleration, mass and existing fin/wing span. The effective finite-wing efficiency is an explicitly chosen game approximation (0.7); no undocumented manufacturer coefficient is claimed. Coast and motor state continue to come from the existing motor schedule.

Known AIM-9X, IRIS-T and R-73/R-73E model identities retain motor-dependent thrust-vector control. A central game calibration assigns at most 0.2 of current primary motor acceleration to additional normal control, within the store's existing total G cap. The diverted thrust pays its axial component loss; only the aerodynamic share pays induced drag. Motor cutoff removes vector authority. This distinguishes published capabilities without claiming a real nozzle angle or exact low-speed G curve. Propellant mass depletion, detailed supersonic coefficient tables and seeker signal processing remain outside this correction.

After launch, retain the same rear-aspect gate and catalog angular tracking-rate restriction used in acquisition. An invalid observation does not update the stored target position/velocity; coast/reacquisition expires on bounded catalog memory. Modern missiles keep their catalog differences instead of receiving a universal damage or G reduction.

The original native countermeasure path had no accepted command/inventory/decoy owner. The implementation below adds that owner instead of copying browser random decisions into damage. Identity, stock, accepted pose and distinct decoy attribution remain explicit native boundaries; client profile/projection and final native build validation are coordinated separately.

Implementation sequence:

1. Add focused tests against extracted current browser physics/seeker functions; observe failures for free maneuver energy and postlaunch aspect/rate bypass.
2. Add a pure JS helper and candidate-only patcher for those exact live functions. Verify the patched artifact passes without modifying canonical app directly.
3. Add matching Rust budget functions/config observations and meaningful Rust regressions; integrate the budget into the existing native projectile step. ROOT runs Cargo tests and rebuilds final WASM/server artifacts.
4. Verify all 33 source entries still parse and preserve authoritative swept proximity/hit/damage ownership. Record countermeasure integration evidence and remaining detailed-envelope limitations precisely.

Primary references: [NASA induced drag](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/induced-drag-coefficient/), [NASA dynamic pressure](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/dynamic-pressure/), [USAF Sidewinder family description](https://www.af.mil/About-Us/Fact-Sheets/Display/Article/104557/aim-9-sidewinder/), [Diehl IRIS-T description](https://new.diehl.com/defence/en/products/guided-missiles/iris-t2). These support the physical principles and generation distinctions; they do not publish enough data to calibrate exact kill probabilities or classified seeker countermeasure rejection.

TVC capability references: [NAVAIR AIM-9X](https://www.navair.navy.mil/product/AIM-9X-Sidewinder), [Diehl IRIS-T](https://new.diehl.com/defence/en/products/guided-missiles/iris-t2), and [US Army ODIN R-73E](https://odin.t2com.army.mil/WEG/Asset/b772e6f643bfe928cd06ea994bc24031). The capability flag is sourced; the 0.2 force allocation is game calibration.

Baseline CM integration boundary: the legacy lobby `AirCm` accepts a kind and a 0.1 s cooldown, then broadcasts; it does not own inventory. Before this change, native `AirUnitView` carried no CM stock or decoy state, exported aircraft profiles had no CM capacities, and `frontline::Command` had no CM release intent. Native `cmRelease` therefore could not keep consuming local cosmetic stock as if it were accepted. The coordinated implementation requires: import the existing `AIR_CM` capacities and variant inheritance into native profile data; add `AirCountermeasure { unit, epoch, seq, kind }` through existing controller/life validation; consume stocks and spawn host-owned decoys from accepted pose/velocity; evolve them with seeded identity and bounded lifetime; filter replicated positions by the existing perception policy; project accepted stock/events back to HUD; and permit matching IR/radar seeker classes to observe those decoys without authorizing hits. Do not invent client-supplied decoy positions or duplicate a second damage owner.

Native countermeasure implementation contract: `air_countermeasure` accepts only `unit`, `epoch`, `seq` and `kind` (`flares`, `chaff`, `both`) after existing control/life/sequence validation. A successful host release consumes up to two actual rounds of each requested available class, sets the existing source 0.15 s dispenser interval, and increments one accepted `release_seq`. Empty, unfitted, stale and invalid releases leave stocks unchanged. Profiles import the delivered `AIR_CM` table and its variant inheritance. Rearming occurs only at the existing completed host-service resource commit; sequence/decoy serials remain monotonic within the life, and already emitted decoys keep their finite remaining lifetimes. A new life starts at full fitted capacity with no decoys.

Accepted decoy emission uses the existing model-local dispenser points `[side*0.6,-0.4,-2]`, transformed by accepted model pose. Initial speed fraction (flare 0.6/chaff 0.3), lateral 8 m/s, downward 6 m/s, lifetime (5/6 s), drag (1.2/3 s^-1) and reduced gravity (0.5/0.15) are retained source gameplay dynamics, not measured countermeasure specifications. Evolution is deterministic. Countermeasure state and decoys remain nested in the already visibility-filtered `AirUnitView`; snapshots carry stable serials and are read-only.

Seeker trials use matching IR versus radar classes, accepted decoy coordinates, host line of sight, aperture, rear-aspect and tracking-rate restrictions. SARH needs accepted radar support; ARH/AIM-54 must reach their active seeker phase. The source resistance coefficients remain explicitly game tuning: `(1-flareResist)^2/4` and `(1-chaffResist)^2/3`, without inventing manufacturer kill or rejection probabilities. A deterministic projectile/decoy seed supplies a single trial only once that decoy is geometrically eligible, so a hidden or out-of-aperture observation does not consume its future trial.

Decoys have a separate `{owner:UnitRef, serial}` identity and a separate observation estimate. No decoy position is ever attached to an aircraft `Target` reference. Once diverted, guidance follows only this decoy estimate and then bounded memory; the original aircraft proximity fuze is disabled for that diverted missile. Decoy disappearance never grants a false aircraft impact, damage or kill. Existing finite swept contact with a real aircraft remains the sole direct-contact path and remains able to hit an aircraft physically intersected by the missile. Harmless lost/lifetime expiry does not invent a decoy blast victim.
