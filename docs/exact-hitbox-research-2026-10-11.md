## Recommendation and exactness contract

Implement a trusted, versioned triangle manifest compiled from the **same float32 local triangle buffers used by the renderer**, plus declared physical roles and stable anatomy bindings. Run one Rust exact segment/crossing implementation in native/server and WASM. Use shared per-mesh BVHs and a refitted per-entity instance tree from the current accepted pose. AABBs/OBBs may reject candidates, but may never decide a final hit.

The promise is exact intersection with the currently accepted, rendered polygonal geometry within documented numerical tolerance. It is not exact historical engineering geometry or arbitrarily shaped real projectile contact. Raw GLB positions differ from packed render positions: current importer rounds to millimeters, then `partVertices` stores float32. The final test must use those actual emitted vertices, not a second raw GLB mesh. Preserve the original GLB and import configuration as provenance. The manifest is a new derivative, never an overwritten asset.

Include all exterior assemblies (hull, every turret, gun/mantlet/barrel, MG/APS, wheels, rollers, sprockets, support arms, rigid track shoes) and the already modeled internals/crew. Hollow regions and gaps contain no collision surface unless an actual triangle is there. An interior mesh hidden by the X-ray display switch still physically exists. A launched missile, consumed exposed round or empty modeled ammunition rack is physically absent according to its trusted state; rendering options must not change this state.

Collision geometry and protection data are different inputs. Existing armor `thickness_mm`, material and weapon/engine calibrations remain trusted authored engineering data. A visible hull is often a solid closed prism used to depict a hollow vehicle; its entire geometric enclosed space is **not** solid steel. Do not infer armor thickness from the hull diameter, from nearest triangles, from imported material roughness, or from a missing exit. Do not assign a decorative lamp, bracket, tarp or bolt the full protection of the nearest hull plate.

## Proposed contracts

Names below are proposed new contracts, not implemented functions.

### Immutable `HitMeshManifestV1`

Publish `data/hit-meshes/index.json` plus binary payloads keyed by SHA-256, with a schema in `schemas/hit-mesh.schema.json`. Generate with a new CPU-only `client/web/tools/export-hit-mesh.mjs`. Keep graphics-free manifest/ray/pose/BVH code in `crates/combat/src/geometry/{manifest,bindings,bvh,ray,pose,surface}.rs`, exported through `crates/design-wasm`; callers provide accepted pose, so `tg-combat` need not depend on physics or a browser. The current shared primitives/pose may be supplied by `tg-physics` and the authority owner without a dependency cycle.

Required data:

- `schema`, format/endianness, generator revision/hash, build recipe hash, immutable `specId`, normalized `buildHash`, `manifestHash`, exact `renderGeometryHash` and `anatomyDataHash`. Include source GLB/archive hash or explicit missing status, packed-model hash, import-config hash and all borrowed donor asset hashes. Binding metadata is part of the manifest hash.
- `meshes[]`: stable mesh key, float32 local positions exactly as emitted (preserve triangle order/winding), triangle indices/ordinal, per-triangle role/binding/solid ID, local bounds and serialized flat BVH. Binary indexed storage may deduplicate only identical position bits without changing triangle vertices/order. Interleaved color/UV bytes are unnecessary for collision, but retain the complete render-buffer hash as evidence.
- `assemblies[]`: stable assembly key, parent assembly, immutable local base transform/pivot, joint descriptor and allowed motion fields; `meshInstances[]` identify mesh key, assembly, stable instance/material feature ID and activity policy. Track instances retain side/material link identity, independent of current packed instance-array order.
- `bindings[]`: armor ID/layer ID, module ID and module kind, crew slot key plus existing index, mounted weapon key, track side/link/feature; refer only to the trusted normalized anatomy table. Use `WeaponBinding.key` (`gun:<turret>:<gun>`, MG instance key etc.), not catalogue gun ID. Crew currently lacks an authored ID, so mint a sidecar slot key pinned to the anatomy hash and ordinal; role alone is ambiguous with multiple loaders. Array reordering requires an explicit mapping/migration.
- `surfaces[]`: declared role and topology (`boundary_shell`, `open_sheet`, `closed_solid`, `decorative_surface`), `armorLayerKey`/`solidKey`/`moduleKey`/`crewKey`, geometric winding interpretation, trusted material-response reference and optional fuse/contact eligibility. Unknown physical/protection roles are build errors, not auto-hull armor.
- `audits`: exact triangle coverage, degenerate count, boundary/nonmanifold edges per declared solid, declared open boundaries, missing/ambiguous bindings and render-buffer differences. Runtime verifies the payload hash and structural limits; build-time audits are independently reproducible.

For existing packed meshes without complete raw source IDs, a stable key is the pinned packed-asset hash + original packed part ordinal + triangle ordinal + immutable mount descriptor. Mint it **before** `decodeAllImported` borrows parts and workshop filtering shifts indices, and preserve it in sidecar tables through export. For a new GLB import add a separate source map `(asset hash, scene-node path/index, primitive ordinal, source triangle ordinal, emitted triangle ordinal, import transform)`. Source node names alone are not unique identities. Record selected/dropped/rebased triangles, including previously removed tools; only actually rendered emitted triangles enter the collider.

### Mapping completeness and merged meshes

Capture procedural triangle ranges when each `addPart` emits them, including face/solid ranges from `GeoBuilder`. Annotation must follow the actual render emission, so a second custom triangulator cannot drift. Mark barrel outer/ring/bore triangles separately but bind the same barrel module. Similarly retain source solid ranges for each shoe primitive, wheel groove/ring, engine piece, ammunition round, launcher apparatus and crew figure. Snapshot R is useful evidence; it does not by itself supply semantic armor bindings.

For imported merged hulls, author a hash-pinned sidecar partition assigning each emitted triangle (or exact patch evaluation at barycentric hit position where an engineering region crosses one triangle) to the existing protection descriptor or a declared non-armored part. Spatial/normal/plate-plane proximity can generate review candidates, but never silently resolve ambiguity. Validate each declared armored patch against its existing armor ID/material/thickness and preserve donor origin. No runtime nearest-plane classification and no old plate intersection fallback.

Acceptance requires **zero unclassified collision triangles, zero missing/ambiguous anatomy references and zero render-position differences**. Count intentionally declared decoration separately. When an armor region boundary runs inside a triangle, use a trusted region partition over that triangle and hit barycentrics; do not label the entire triangle by its centroid. This changes metadata only, not protected geometry. A shared imported part may have different protection bindings in a variant, so mesh-buffer sharing and binding-table sharing are distinct caches.

### Per-entity `AcceptedHitPoseV1`

Separate immutable specs/builds from actors: `entityId`, `spawnEpoch`, `buildHash`, server-generated `poseTick/poseRevision`, accepted sample timestamp. Two players may use the same spec with different folds, damage, joints, running gear and crew state. Respawn/workshop swap invalidates old actor instances and bounds. Pose revision is an authority receipt, not an arbitrary client number.

Semantic fields, reconstructed by shared pure functions:

- Full hull origin and accepted orthonormal basis/attitude; all parent-relative turret yaw values, not just main yaw. Explicitly convert any current hull-relative child yaw to parent-relative node yaw exactly once.
- Every gun's elevation, firing/recoil phase and current recoil translation; hinge fold fraction, MG/APS yaw/elevation/barrel spin where applicable. Bounds include the real moving mesh reach, not an arbitrary main-turret radius.
- Wheel lift, axle steering, spin and idler offset from accepted running-gear state; use actual imported wheel triangles for the hit query even where physical wheel-ground contact remains an engineering proxy.
- Immutable link count/pitch/features from the trusted descriptor; phase, B accepted frozen closed shape or physical world chain nodes, broken topology/cut pin/revision and detached-chain sleep state. Reconstruct each rigid shoe's transform using the same pins as rendering. A fallen chain's world anchor must not move when its hull moves.
- Launcher per-instance readiness/next-tube/loaded payload and ammunition occupancy; module/crew existence state and deterministic animation phase/firing history. X-ray/scope/LOD/fade flags are absent from physical activity.
- Explicit geometry/deformation revision. Current vehicles have rigid node transforms; any future dent/bend/skin/morph must supply trusted changed vertices or a shared deformation evaluator and refit/rebuild affected BLAS before publishing pose. Shader-only untracked displacement is an audit failure.

Browser physics/render interpolation can choose a presentation sample; exact query must name the sample it uses. Update matrices and physical instance bounds atomically from that sample before querying and before rendering it. Do not read previous-frame `Node.world` alongside new suspension pins. If renderer and authority samples differ because of remote interpolation, the result must identify the accepted authority sample; same-pose parity is the test, not equality between different times. Exact moving-target projectile CCD across time needs pose-aware continuous sweep/relative-motion handling; freezing a pose per ballistic substep has a documented approximation and cannot be sold as continuous-time exactness.

### `SurfaceCrossingV1` and protection resolution

Return sorted crossings with `entityId/spawnEpoch/buildHash/poseRevision`, stable assembly/instance/mesh/triangle/solid/binding IDs, fractional segment `t`, world point, barycentrics, **geometric** world normal, facing normal, `enter|exit|touch|sheet`, physical role and trusted response reference. A shading normal or normal map is not a penetration normal. Retain unclamped geometric orientation for enter/exit; a facing normal is only the normal used for incidence/reflection.

The impact/energy pipeline consumes these crossings. It must not perform another plane raycast and relocate contact. Start with the caller's actual segment (or authority-generated ballistic segment), not the old two-meter offset/full-target ray. Additional traversal after penetration uses a cursor/remaining distance against the same geometry and new trajectory/energy state. Cache geometry, not outcomes, across shots.

Closed solid enter/exit pairs are valid only for a certified consistently oriented solid component. For composite procedural solids, retain per-primitive solid keys and union their occupied intervals **only when declared as one physical material/component**; overlapping engine boxes or gun rings must not charge the same module/armor layer repeatedly. A real air gap between occupied intervals remains a gap. Deduplicate shared-edge contacts only within the same declared surface/solid; distinct co-located armor layers cannot be globally deduplicated.

An open sheet has a triangle contact, not a guaranteed closed volume. Its declared authored thickness can resolve resistance and a separately marked engineering backface/spall origin without adding a new visible collision triangle. `boundary_shell` means a vehicle compartment boundary, not the whole enclosed volume being material. A closed visible hull envelope may locate near and far wall contacts while existing engineering thickness protects each bound wall patch. An actual modeled tube's bore remains empty and ring/bore wall contact is real. For closed solid material without known wall engineering data, geometric occupied length is geometry evidence only; no new steel density/hardness/thickness may be invented.

No missing-exit fallback such as `entry + .01`; no clipping the trusted armor thickness to an artistic mesh span. Report open/ambiguous topology and stop the publication gate for a role requiring a volume. Interior/compartment classification for overpressure must use explicit trusted boundary/opening metadata and the same crossings; a single `inside=true` after one entering armor plate is insufficient. Starting inside, leaving a compartment, hitting a far wall from inside, open-top entries and outward fragments all need explicit transitions. Outgoing contact is still contact, with appropriate inner-face direction; it must not be silently skipped or cause the same entry layer to be charged twice.

Existing internal targets get their current modeled triangle meshes. A ray through the modeled V-engine bank gap, between ammunition rounds, beside a loader's arms or through a handwheel opening may pass. Do not enlarge these bodies to previous boxes/spheres to retain old hit rates. Anatomy health, module resistance/calibration and capabilities can retain existing rules while the shared impact pipeline is updated separately. An authored module with **no existing model** is audited as missing geometry, not assigned an invented exact mesh. Map existing exterior barrel/track geometry instead of generating new module boxes. Dead or destroyed solids remain or disappear according to a declared physical rule; health zero alone is not a license to delete visible metal.

## BVH and segment implementation, in the first delivery

1. Build a deterministic flat binary BLAS for each immutable local mesh using 16-bin SAH, stable triangle-ID tie breaks and leaves of at most 8 triangles. Serialize it with the manifest or build once on load; validate ranges, cycles and conservative bounds. One BLAS is shared by every identical crew figure, wheel and track shoe. Keep original triangle order separately from BVH permutation.
2. Maintain a small TLAS over current active **instances** for each entity (and an entity-level world filter). Refit affected leaf/world bounds and ancestors after accepted pose changes; topology/activity change rebuilds the instance leaf table. Current full matrices and inverse matrices are scratch/cached, derived internally. AABBs use conservative floating-point outward padding only to avoid false rejection.
3. Traverse world segment candidates in nearest-first order. Transform both endpoints to instance-local coordinates and use `D = B - A` without normalizing: `t` remains the same fractional segment coordinate under affine transforms/nonuniform scale. Reject nonfinite/singular transforms, not fall back to AABB final contact.
4. Use one double-sided **watertight** ray/triangle implementation (dominant-axis permutation/shear and robust edge tests; f64 fallback for zero/near-zero edge expressions). Limit `t` to the query segment. Rust native and WASM execute this same code. Do not broaden triangles with a gameplay-sized epsilon that closes narrow holes. Derive geometric world normal from transformed edges, or inverse-transpose with determinant sign, rather than the interpolated vertex normal. Negative determinant winding is handled explicitly.
5. Gather all ordered crossings required by penetration/fragment traversal, not only nearest. Stable tie order is `(t, instanceId, solidId, triangleId)`. Handle shared edges/vertices once, coplanar tangencies as declared touch events, inside starts and multiple real exit/entry intervals. Preserve exact topology adjacency/solid IDs so numerical dedup does not merge separate shells.
6. Refit/rebuild only the changed BLAS for actual vertex deformation. Ordinary fold/elevation/recoil/wheel/rigid-shoe motion changes TLAS transforms only. Use reusable stacks/event buffers with explicit growth/overflow handling; never silently drop a crossing when a buffer is full.

CPU float32 input and matrix multiplication imply finite tolerances. Preserve local position bits and submitted instance matrix bits for render-buffer equivalence; perform queries in f64 over those vertices/transforms. State error bounds with scale/ULP awareness, e.g. position within a few float32 ULPs plus a small absolute term near the origin, and crossing `t` within a specified normalized tolerance. Do not promise literal bit equality with every GPU fused-operation implementation. The same core must return the same ordered identities and materially equivalent points for native/WASM under the same pose. An exactly-on-edge ray has a deterministic documented owner; it is not an excuse to fill nearby empty space.

## Native/server trust and workshop publication

Stock server startup must load `HitMeshManifestV1` from the server installation and verify its SHA-256 against an allowed catalog/index, plus bound armor/module/crew/weapon data hashes. The browser receives that same manifest hash/build receipt and uses the same normalized anatomy. A client may name an allowed immutable manifest; it may not upload arbitrary triangles, replace binding tables, declare a thinner armor layer, or choose its own transform matrices. Pin the catalog hash in the deployed artifact or approved publication receipt; hashing attacker-controlled bytes and then trusting their self-reported hash is not verification.

Current workshop builds are local and online rooms accept stock IDs. Preserve that boundary until a trusted normalized workshop publication path exists. For approved workshop online support, server intake accepts only semantic build selections/parameters within limits, checks base/donor catalog IDs and permissions, normalizes the build, rederives its values using trusted source/calculation rules, then produces or verifies the canonical triangle manifest and signs/stores a build receipt binding `buildHash/manifestHash/anatomyHash/catalogVersion`. A JS exporter running in the **trusted build process** is a practical way to use the existing generators while Rust receives graphics-free binary geometry; it is not an arbitrary client mesh upload. The receipt does not replace runtime catalog/data hash verification.

`tg-design::accept_submission` already rejects client-derived values for the design bureau, but the workshop compiler is a separate JS path; it is not automatically server-authorized by that function. If trusted server-side workshop normalization is not yet implemented, local exact workshop hits can be supported using its local trusted generated manifest, while online publication remains unavailable. Do not disguise this as server parity for online custom builds.

Authority must choose accepted defender pose itself. Validate/reconstruct hull/joint fields from motion/input history, authored limits and rates, reload/fire/capability state, accepted timestamps and connection serial. Recoil comes from a server-known firing event; payload comes from server ammunition/launcher instance state; fold from accepted constrained defender state. Server assigns pose revision. Move from client-claimed local shot yaw/speed/distance to the validated fire record and shared ballistics reconstruction (root impact-state work). A client's `hit`/pose revision can be a hint for lookup, never authority over geometry, angle or energy.

Physical track B is a real dependency. Task 2 currently leaves `lowerGraph.enabled=false` in both JS and Rust; current hit work cannot certify its future accepted broken chains. B's spec requires server-held `epoch/revision/broken/cutPin`, accepted bounded `q/qv/phase/idler/shape`, canonical frozen residual validation, world chain nodes and close-repair generation/serial checks. Exact colliders must consume that **accepted** semantic running-gear data and its shared reconstruction. Validate count/pitch/length/finite bounds/terrain feasibility/topology and chain constraints independently; range checks or a plausible poseRevision alone do not make owner-supplied shapes trustworthy. Do not replace imported wheel hit meshes with B's finite wheel-ground engineering proxies, and do not fall back to wheel circles or an intact closed belt after a broken-chain state.

A malformed or missing new pose extension may retain a valid legacy movement packet for compatibility, but exact hit mode must identify that it lacks the required accepted geometry sample. It cannot falsely certify stale/default intact geometry as exact. New-protocol peers need a complete canonical keyframe on spawn/reconnect; legacy handling must be explicitly versioned and excluded from exact-mode acceptance until all collision-critical states can be reconstructed.

## First practical implementation tasks and measurable gates

### First bounded Hx task after R and the shared impact kernel

The first implementation does not need to await a complete 42-vehicle binding audit or full online B authority. Deliver the static geometry library and its format first, with the recorded Hetzer gap/tube fixtures and a trusted immutable neutral-pose manifest for selected stock models. Include existing internal/crew mesh inventory in that export; treat unreviewed protection roles as **pending audit in the research/export report**, never as a runtime armor fallback or a certified exact vehicle. This task is geometrical query infrastructure and does not yet claim fleet damage completion.

Suggested concrete APIs:

```text
GeometryCatalog::install_trusted(expected_manifest_hash, manifest_bytes)
    -> Result<ManifestHandle, ManifestError>
GeometryCatalog::bind_actor(entity_id, spawn_epoch, manifest_handle)
    -> ActorGeometryHandle
ActorGeometry::publish_pose(accepted_pose_from_authority)
    -> Result<PoseReceipt, PoseError>
ActorGeometry::segment_crossings(p0_world, p1_world, pose_receipt, scratch)
    -> Result<&[SurfaceCrossingV1], TraceError>
ActorGeometry::release(entity_id, spawn_epoch)
```

`install_trusted` receives its expected hash from the native server catalog/trusted local build, not from the mesh submitter. `publish_pose` is an internal call accepting the semantic pose type; it is not a wire endpoint for arbitrary matrices. Define distinct error types for missing manifest, stale actor/pose, invalid topology, unsupported deformation and unresolved physical binding, so callers cannot turn any failure into a proxy hit.
