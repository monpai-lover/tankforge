## 建議優先順序

第一優先是**機制、傳播路徑與能量帳正確**，第二才是材料與歷史炮彈的數值校準，第三才是更細緻的變形／碎裂畫面。

目前已有穿深、跳彈、破裂標籤、裝甲剝落、爆炸碎片和乘員／模組傷害，但「彈體完整度」沒有貫穿這條鏈。把畫面上的完整彈頭換成碎塊，不能單獨解決損傷真實性。適合即時遊戲的第一版是每次碰撞更新一個小型彈體狀態、有限碎片群與明確能量預算，沿用既有幾何和原始資料；不需要在每顆彈上運行完整有限元素／流體模擬。

配套的超壓調查見 [overpressure-research-2026-10-11.md](overpressure-research-2026-10-11.md)。外部爆炸、破口進氣、真正艙內起爆與裝甲應力波／剝落應分開；不能讓新的碎裂功能重新引入「穿過任一薄板便全車超壓」的捷徑。

## 已查證的物理現象

### 變形、破裂與裝甲剝落不是同一件事

鋼製彈體的硬度、材料及碰撞條件會改變塑性變形和斷裂模式。把彈體永遠視為不會破壞的剛體，可能把實際彈體碎裂誤算成目標被穿透。[Rakvåg、Børvik、Westermann、Hopperstad，2013，SINTEF 提供的研究摘要](https://www.sintef.no/en/publications/publication/0198cc42deb0-f2bc0250-a605-4f8e-935e-f95c52836d5b/)

斜向穿甲實驗亦觀察到彈芯碎裂與板厚、斜角相關；該研究需要針對特定彈芯材料測試、反推材料參數。這支持保留跨層完整度，但不支持把其中一組材料常數套到所有炮彈。[Paris 等，2012，研究機構摘要與原論文 DOI](https://cris.bgu.ac.il/en/publications/fragmentation-of-armor-piercing-steel-projectiles-upon-oblique-pe/)

應至少分辨：

- 彈體變形：鈍化、壓扁、彎曲；仍可能保有一個主體。
- 彈體破裂：裂成數個或更多彈芯／彈體碎塊。
- 彈芯侵蝕：穿透時主體的質量／有效長度逐漸消耗，尤其不可把長桿彈永遠當完整全長剛體。
- 裝甲剝落／塞塊：來自目標的金屬，與彈體碎塊有不同質量來源。
- 起爆後彈殼碎片：由爆炸加速，另有化學能來源。

### 殘餘速度不足以描述殘餘殺傷

FFI 的陶瓷／複合覆層實驗同時回收彈芯碎片並量測殘餘速度、質量分布和動能損失；不同目標配置的速度差異沒有質量／動能差異那麼大。速度仍高的殘塊不代表原本整顆彈的質量和能量仍在。[Rahbek、Johnsen，2019，FFI 研究頁](https://www.ffi.no/en/publications-archive/fragmentation-of-an-armour-piercing-projectile-after-impact-on-composite-covered-alumina-tiles)

長桿侵蝕彈的實驗則把幾何比例、材料與侵蝕放進分析；簡化解析模型也存在適用範圍，不能代替每一種彈芯的量測。[Zaki、Uddin、Mubashar，2020，出版社研究摘要](https://journals.sagepub.com/doi/10.1177/1464420720940766)

第一版至少應保存質量、速度、主體完整度及碎片來源。數值上的 `E = 0.5*m*v²` 是動能帳，不是穿深公式，也不是人體死亡公式。相同動能、不同質量、形狀、接觸面積與命中位置，不能直接判成相同破壞結果。

### 被帽、風帽與脫殼

美國陸軍歷史手冊分別描述穿甲彈、保護彈頭並分散撞擊應力的穿甲被帽，以及離開炮口後丟棄彈托的 APDS。[TM 9-1300-200，1969，p.4-7；本次從大學保存的原手冊讀取 PDF 第80頁](https://www.ibiblio.org/hyperwar/NHC/NewPDFs/USArmy/US%20Army%20Technical%20Manuals/USArmy.Ammunition%20General%20TM%209-1300-200%201969-10.pdf)

因此引擎應區分發射時的組件、飛行中的主彈與接觸裝甲後的殘塊。被帽／風帽不能都當作無限重生的穿甲增益；APDS 的炮口彈托也不能在艙內變成額外穿甲質量。手冊中的特定歷史組成不能當作所有年代、所有 APDS／APFSDS 的材料配方。

### 未穿透亦不等於沒有任何效應

彈體和目標都可變形；目標的快速背面變形也可能產生傷害。NIST 對防彈衣的說明清楚區分了阻止穿透與背面變形。[NIST：How Do You Test Body Armor?](https://www.nist.gov/how-do-you-measure-it/how-do-you-test-body-armor) 此來源是個人防護裝備，不是戰車艙內校準；不能把其測試限值直接拿來算車內乘員死亡。

對 TankForge 的推論是：停止、跳彈、碎裂可以有外部碎塊、有限的局部裝甲效應；若沒有氣體或固體通路，不應把碎塊放到裝甲內面傷全艙。背面剝落若要在「未穿孔」時發生，需獨立且有依據的判據，不能凡未穿透都生成。

## 即時縮減模型建議

以下是物理啟發的工程設計建議；比例／曲線仍需標明估計，不是從上述研究取得的通用材料校準。

### 1. 小型且可重播的彈體狀態

每個存活主彈／代表性碎塊至少記錄：

| 欄位 | 單位／含義 |
|---|---|
| `mass_kg`, `velocity_m_s` | 當前飛行主體質量、速度向量 |
| `energy_j` | 由質量與速度計算；不能與它們各自獨立漂移 |
| `remaining_length_m`, `effective_diameter_m` | 有來源時為幾何；否則標記工程估計／未知，不能混用口徑與subcaliber彈芯直徑 |
| `deformation`, `integrity` | 0..1的工程狀態量，無物理單位；不得把值宣稱成實驗斷裂應變 |
| `cap_state`, `piece_source`, `parent_event_id` | 被帽有無／消耗、彈體或目標來源、生成事件 |
| `fuse_armed`, `fuse_elapsed_s`, `detonated` | 引信狀態、實際經過時間、是否已起爆 |
| `profile_id`, `model_revision`, `source_status` | 所用工程參數與版本；`measured/authored/estimated/unknown` |

讀入原始炮彈規格，另外建立版本化工程 profile。不要覆寫原資料，也不要因一個kind就替所有彈推定同一彈芯密度、質量比例或韌性。可從既有 `Apcbc` 開啟被帽狀態的估計功能，但被帽強度與失效條件若無來源，必須保留其估計身份。

### 2. 每個碰撞只有一份能量帳

固體碰撞的記帳形式可為：

`E_in = E_out_core + E_out_projectile_pieces + E_out_armour_debris + E_target_deposition + E_deformation_fracture + E_unresolved_loss`

所有項≥0，輸出不可超過輸入（容許明確數值誤差）。目標可以提供剝落質量，但不會憑空提供動能。不要先產生一群能量總和為主彈殘能的spall，再讓主彈帶著同一份殘能繼續命中。碰到下一模組／乘員也從同一能量帳扣除，只把當地沉積的部分交給傷害曲線。

第一步可以保留原穿深曲線和目前殘速近似作相容基準，再把其消耗轉成明確的估計 work：例如現有 `q = required_mm / available_pen_mm` 與 `sqrt(1-q²)` 對應 `W_proxy = E_in*q²`。這是**現有遊戲公式的能量化近似**，不是 Recht–Ipson／材料實驗推導，也不能宣稱修正後即符合真實材料。

主彈、彈體碎塊及裝甲碎片應從被明確劃出的工作／殘能預算分配；未能模擬的部分放到 `unresolved_loss`。分裂後的速度由每塊分配的 `E,m` 一致求得。對很小質量需有有限值與步進上限；不能為避免除零而製造額外質量／能量。

質量也分來源：彈體主體＋彈體碎塊不超過該飛行主體的初始質量；彈托／被帽不能重複成為彈芯。裝甲碎片可另有目標質量預算，從局部板材／估計受損體積導出並標記估計，不把整個炮塔的金屬都交給一個命中事件。

化學能只在可信起爆事件上釋放一次。若要估計彈殼碎片能量，使用有來源的填藥／炸藥能量資料及明確耦合近似；沒有來源不能把任意字串當TNT。空氣超壓與固體碎片不能各自無限制领取一份完整化學能；同時不能把壓力衝量的數值當焦耳直接加進固體能量帳。

### 3. 變形、碎裂和侵蝕各走自己的狀態轉移

- 完整或輕度變形：主彈繼續，降低其可用能量；被帽／風帽消耗記入同一事件。
- 明顯塑性變形：更新工程 `deformation`、有效幾何與後續穿透能力，保留主體；這不等於已經碎裂。
- 碎裂：主體可保留一個較大殘塊，其餘質量／能量分配給有限的projectile pieces；沒有通路的碎塊只能留在板外，不因 `Shattered` 標籤自動放到內面。
- 長桿侵蝕：更新殘長、殘質量及方向／完整度近似；消耗不能每層重設。不要對所有APFSDS強制套同一鋼製短彈碎裂條件。
- 跳彈：保留被撞擊損傷的狀態，算有限且不增加能量的離開速度／方向。主體方向若變了就重新求交。鏡面反射可作第一版方向近似，需標記；不是零耗能的彈性反射。

可先以現有 `shatter_angle_deg`、材料分類和已消耗工作作兼容的有限判據，將其標記為 heuristic。新的動態屈服、韌性、fragment-size分布等參數只在有來源時使用；不得從「BHN≥350」或任一口徑推出通用破裂／殺傷結論。

第一版應先保證碎裂後狀態真正影響下一層／下一碰撞，並把碎塊送入同一幾何與能量管線。材料曲線之後逐族校準，避免一次把所有历史炮彈改成無來源係數。

### 4. 有限碎片群，不是無限制微粒

建議代表性sample上限先以每事件64條物理射線起步，並有整顆shot共享的segment／collision／continuation上限；這是**效能預算**，不是宣稱真實只有64片。依效能量測再調整。

每個代表性碎塊保存來源、質量、能量、方向、開始時間，總預算按生成事件核帳。不得在增加sample數時增加總質量／能量。應使用確定性seed與穩定事件／板ID；物理亂數和純視覺粒子亂數分離，改FX數量不能改乘員傷害或彈藥架殉爆。

採swept segment／ray與posed裝甲、模組、乘員求交，更新傷後殘能；再碰裝甲應進相同有限碰撞helper。用visited/事件次序和最小進展距離防止同板重撞無限迴圈。耗盡效能預算時把未解析部分記錄，不能偷偷把剩餘能量全部給最近乘員。

純視覺碎片可以更多，亦可只在高品質設定顯示；它們不具有傷害權限。資料不足時不要把工程sample命名成「已量測真實破片分布」。

### 5. 各彈種的最小機制

| 彈種 | 第一版物理狀態 | 碎片／爆炸的邊界 |
|---|---|---|
| AP | 主體變形、完整度、可能破裂；逐層殘能 | 彈體碎塊與目標剝落分開；無填藥不產生爆炸 |
| APCBC | AP狀態＋被帽／風帽可消耗 | 被帽是組件狀態，不能每層重新獲得保護；是否帶填藥依原始資料，不能只依縮寫 |
| APCR | 主體組件與已知／估計彈芯分開 | core質量不是固定0.35對所有彈；外部套體不自動全數進艙 |
| APDS | 脫殼後的飛行彈芯狀態 | 炮口彈托已棄；不能在目標內增加彈托質量、能量或破片 |
| APFSDS | 殘長／殘質量與侵蝕／彎曲近似 | 不保證永遠完整、不把每層侵蝕都重設；材料／幾何未知保留估計身份 |
| APHE／帶填藥APCBC | 動能狀態＋獨立引信／填藥狀態 | 依真實經過時間起爆；未啟動、失效、內爆與過穿外爆分開。碎裂不自動全爆或全啞火 |
| HE | 接觸／可信引信起爆、彈殼碎片 | 外部碎片要碰裝甲才能進入；進氣路徑另算，不把起爆點搬入艙內 |
| HESH | 外部接觸爆炸與裝甲應力／背面剝落 | 不以spall判據當gas breach；目標碎片不能叫彈頭碎片 |
| HEAT／HEAT-FS | 爆炸啟動射流的有限penetration potential／jet state | 射流來源為化學作用；不要以彈體撞速直接放大同一warhead的jet預算。彈體動能可另記，但不能混成jet質量 |

HEAT 機械射流與HESH剝落的可靠來源及超壓限制已在前一份調查列出。此表是縮減模擬設計，不是完整historical shell calibration。

### 6. 引信與超壓共用事件

引信開始、延遲與起爆是彈體狀態的一部分。移動一段距離後按當時速度累計時間，而不是永遠用第一次穿板的速度預算一個固定起爆距離。不能為了讓畫面顯示內爆而把爆點clamp到艙室內。

起爆時先判斷爆點環境與氣體通路：`InternalDetonation`、`BreachIngress`、`ExternalExposure`；`ArmourShockSpall`不冒充氣體。彈頭碎裂、彈殼裂縫或靜態圖形洞口不等於艙壁破口。新的固體碎片要沿幾何碰撞進艙，超壓則使用自己的開口／艙室路徑近似。

## 權威狀態與畫面資料

`server/lobby.rs:1339–1348` 已從伺服器炮彈catalog取得shell與seed，`:1415`重新計算combat。但 `shot.speed`、`shot.dist`與局部命中線仍由客戶端claim輸入；目前有限值／速度上限／合理性檢查不等於完整權威外彈道。引入能量損傷後，可信撞速更重要，不能把「數值在0..2000內」當作物理驗證。

後續應由伺服器的已驗證發射事件／飛行狀態取得碰撞速度與位置，或至少以可信炮彈、時間、外彈道可達範圍核驗claim。不可接受客戶端提供的完整度、殘餘能量、碎片名單、破口或crew damage作最終結果。

新的外部碎片、跳彈續飛與附近爆炸若會傷害另一車，必須有伺服器世界碰撞／事件去重。現有 `splash` 的伺服器接點缺口仍成立；只有WASM helper和本機 `splashNear` 不能提供多人權威近彈。局部模型與單車Report可先改善，但不要聲稱跨車碎片／近彈已支援。

建議在Report增加兼容的機制紀錄：

- 逐碰撞 `event_id/source/entry/exit/timestamp/energy_before/energy_after/mass_before/mass_after/integrity/deformation`。
- 碎片來源明确為 `projectile_piece/armour_spall/casing_fragment/jet_fragment/core`，以及source plate／parent event。
- 氣體路徑是blast event，不能用一條“碎片射線”假裝壓力波。
- 純視覺提示記錄damage state，可畫出鈍化、斷裂或侵蝕後形狀；客戶端按事件播放，不重算penetration。

保留舊字段／serde defaults與明確adapter，避免舊consumer只认识 `is_penetrator=false` 就把所有碎片畫成spall。真實到达時間應來自事件記錄；固定6m跳彈線若保留僅可叫視覺提示，不能被當作已模擬路徑。

## 有意義的測試矩陣

| 測試組 | 觀察目標 |
|---|---|
| 基本SI能量 | 質量固定時速度減半動能為四分之一；零能量不產生正固體傷害；NaN／負質量拒絕 |
| 每層能量帳 | 主彈＋彈體碎塊＋目標碎片＋沉積／損失不超輸入；多層不可重複信用相同殘能 |
| 分裂質量 | outgoing projectile pieces總質量不超飛行主體；裝甲質量另有來源；沒有full shell mass duplicated in core與casing |
| 變形未碎裂 | 明顯鈍化仍可有一個主體；後續穿板能力依狀態，不在下一層重設 |
| 碎裂未穿孔 | 碎塊出現於正確外面，能量下降；封閉甲後乘員不受無路徑碎塊傷害 |
| 破裂後仍有殘塊 | 若有可達路徑，有限殘塊可命中模組；Shattered不等於所有物質消失 |
| 被帽／脫殼 | APCBC被帽消耗跨層保留；APDS在艙內不再次產生炮口彈托；未知core mass標記估計 |
| 長桿侵蝕 | 殘長／質量不增加；不與steel short-shot fracture共用一個無條件斷裂率 |
| 跳彈 | 後續速度有限且能量不增，離開方向重新求交；不可重用原射線事件列表 |
| 模組與乘員串列 | 每一hit消耗當地沉積能量；擊中第一目標後第二目標只能使用殘餘預算 |
| sample預算 | 增加物理sample數不增加總質量／能量；FX sample數不改任何state／RNG結果 |
| 微粒／高能穩定性 | 不出現除零／無窮速度／無限同板重撞；預算耗盡可診斷，不將全部未解析能量交給crew |
| APHE引信 | 未啟動、減速後延遲、破裂、過穿、內外起爆各有不同事件；不可clamp入艙；每charge只起爆一次 |
| HE外爆／HESH／HEAT | 外部碎片撞甲；HESH只有spall時無假內爆；同warhead不同launch impact speed不憑空改jet來源能量 |
| 原有完整AP基準 | 原始穿深資料與目前兼容规則保持可對照；改動僅由清楚的state／預算因素解釋 |
| 多owner一致 | combat、design／stack、WASM與server同一impact helper輸出一致；舊adapter有來源類別兼容測試 |
| 權威输入 | 偽造impact speed／mass／piece list不能增加damage；炮彈定義、seed與狀態來自server |
| 多目標與回放 | 同事件／目標去重；同车型不同entity不混淆；回放能正確區分彈體、裝甲與彈殼碎片 |

測試以合成幾何與可核帳事件為先，再針對原有歷史車輛／炮彈做回歸。校準時使用獨立量測，不用同一模型產生自己的真值。不要增加「某口徑一旦命中必死」「碎片數越多必然死更多人」這類假物理測試。
