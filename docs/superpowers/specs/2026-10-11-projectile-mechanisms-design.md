# 炮彈機制、碎片與回放設計

日期：2026-10-11。使用者要求各彈種的變形、碎裂、穿透、爆炸和細節效果，並要求 hitbox 與模型一致。沿用已採用的模組損傷核心 A，與履帶 B、殉爆姿態凍結 R 配合。研究文件：`docs/projectile-damage-reality-research-2026-10-11.md`、`docs/overpressure-research-2026-10-11.md`。

## 完成標準與精度

實作可核帳、可重播、各彈種機制不同的即時縮減模型。真實材料響應取決於彈芯、裝甲、撞速和角度；目前沒有每顆彈的試驗材料常數，不承諾每次射擊都與現實結果完全相同。保留原有歷史車輛／彈藥／裝甲資料，衍生工程 profile 顯示其來源及估計身分。計算正確性、已讀研究支持的機制、歷史校準和畫面驗收分別記錄。

傷害與回放由同一 Rust 結果驅動。純視覺 sample 不改傷害 seed、乘員／模組健康或殉爆；不把外觀上的火花／爆球当作新伤害。全部要求完成後才交付；分階段提交不代表完成。

## 一份跨碰撞彈體狀態

在 `tg-penetration` 中增加純計算 impact owner，供單板、stack、combat、design、sim-slice 共享。動能彈的飛行主體包含質量、速度向量、殘餘穿深、長度、有效直徑、完整度、變形、被帽狀態、累計經過時間及引信狀態。質量／長度不能在下一層重設。`E=0.5*m*v²` 是其動能，不能作為未校準的穿深公式或人体死亡阈值。

原始 `mass_kg` 對 subcaliber 可能是發射組件而非彈芯；現有 APCR .35／APDS .6 比例若缺量測，只可作版本化的沿用工程估計，明確保留 profile 來源。APDS 命中時已脫殼，艙內不再生成完整彈托。APFSDS 適用殘長／侵蝕近似，不無條件套鋼短彈破裂閾值。

每次碰撞記錄 incoming/outgoing 狀態及一份能量帳：

`E_in = E_core_out + E_projectile_pieces + E_armour_debris + E_target_deposition + E_deformation_fracture + E_unresolved_loss`

所有項有限且非負。生成碎片不能再把同一份能量交給前進主彈；接著命中模組或乘員時，只將局部沉積能量送入傷害響應，剩餘部分繼續前進。彈體主塊＋彈體碎塊質量不超其飛行初始質量；裝甲碎片有獨立目標來源與局部質量預算。

第一步沿用單層的原創兼容近似 `q=required_mm/available_pen_mm`、`W=E_in*q²`，但由共用 helper 對每個声明的物理层穿越更新；stack 不再另算一份不同的總殘速。這是舊規則的一致化，非宣稱來源推導的材料法則。公式允许分离实体板与一块整板具有不同的工程结果；三角化、重叠构造primitive和弹道子步不得把同一物理层拆成新板。保留 layer／traversal ID、入层时 state 和 work cursor；部分步只消费累计work的增量，完整同板split／unsplit结果一致。真正离开再返回是新的穿越，不能与同一次穿越的共享边重复接触混淆。從 W 劃出有限的裝甲剝落／變形／沉積份額；若 profile 需要從殘能分裂主彈，主彈也扣掉該份。任何估計 share 都具名、版本化、有適用彈種且標 authored／estimated；不憑 BHN 或口徑編造動態韌性。

彈體組件有有限、非重生的 core／casing／cap／liner／filler mass reservoirs，分配总和不得超过初始飞行体质量，未知划分使用有版本的工程估计。APHE碎裂后只有一个存活 charge-bearing owner 和一个 charge ID，可以继承引信；其他碎块不能复制填药或引信。若生存状态未知，选择明确标记为估计的失效／未解析 disposition 并记录，不凭破裂标签复制爆炸。延迟起爆的弹壳质量来自该时刻剩余reservoir，不取原始0.85倍整弹重重新生成。化学释放单列输入／固体加速／爆压耦合／未解析账；已有平移动能按实际幸存组件分配，不能与爆炸加速重复计算。每个charge ID只释放一次。

## 彈種的行為與小效果

| 彈種 | 判定／傷害 | 回放與外部細節 |
|---|---|---|
| AP | 殘餘彈體、裝甲剝落；可能鈍化／彈體破裂。無填藥不爆炸 | 主彈鼻端鈍化／殘塊、從板背面發出的裝甲碎片、正確停止／離開位置 |
| APCBC | 動能狀態；被帽／風帽消耗跨層保留；有填藥者另走 APHE 引信 | 被帽脫落與主体分開，不能每層重新生一套被帽 |
| APCR | 彈芯與套體來源分開；套體不自動全進艙 | 較窄彈芯與有限套體碎塊，各自有實際起點 |
| APDS | 飛行彈芯的殘能／破損／剝落 | 命中呈現彈芯，炮口脫殼只作炮口事件，不在目標裡增加彈托 |
| APFSDS | 侵蝕／彎曲／殘長與完整度近似 | 可縮短的長桿主體、分出的彈芯殘塊，不永遠保留全長 |
| APHE／填藥 APCBC | 依靈敏度啟動、實際時間延遲；合法起爆才加入化學能 | 先穿板前進，再在實際引信位置爆炸；彈殼碎片、壓力暴露和裝甲碎片分開 |
| HE | 真實外爆位置、彈殼碎片、有限破口候選；逐層驗證主甲 | 外表接觸爆炸、撞甲後停止的外部碎片；破口連通才顯示進氣路徑 |
| HEAT／HEAT-FS | 外爆生成金屬射流，有限射流狀態、間隙與多層耗散；彈體撞速不提高同裝藥射流預算 | 爆點留在接觸面，狹窄高速射流與背面碎片；不是完整炮彈穿艙，也不是氣體燒穿 |
| HESH／HEP | 接觸爆炸造成裝甲應力／背面剝落；剝落不等於通孔或艙內起爆 | 板背面碎片從板內側起飛，彈體留外部；无通孔不画射流／假內爆 |
| Smoke | 保留煙幕用途；原資料無破片裝藥時不借用 HE 傷害 | 原煙幕效果，正常命中提示；不凭名称创造杀伤 |

停止、跳彈和未穿孔破裂可有外部碎塊及變形，但沒有固體通路時不能把碎塊直接放到內面。後續方向改變必須重新求交，不沿用原射線預排事件。跳彈的殘速有限且能量不增；若只畫解釋線，必須和實際續飛分開，最終跨車命中仍由權威 owner 计算。

## 碎片傳播與效能

碎片種類為 `core`、`projectile_piece`、`armour_spall`、`casing_fragment`、`jet_fragment`。每個生成事件有 stable ID、parent ID、source plate／module、mass、energy、速度及開始時間。可保留舊 kind／is_penetrator 作 adapter，但不能再把所有 false 都映成 spall。

初版整顆 shot 最多64條代表性物理碎片射線，合計256段，每個 continuation 最多16次碰撞；這是計算預算而非真實碎片數。每条代表射线保存 individual physical fragment mass／energy／area／velocity 与独立 multiplicity／weight，不能把计算sample的总能量当成单片能量送入sqrt(E)穿深／伤害公式。碰撞／衰减按单片物理参数计算，质量／能量总账和局部沉积按weight核算；同源同轨迹的加权样本先按stable parent/crossing归并再施加健康和次生RNG事件。把一条射线复制成两条半weight时，路径、总预算、健康／殉爆RNG结果必须不变。方向重新抽样时做有界收敛检查，不声称不同方向样本完全相同。增加 sample 不增加總質量／能量，也不得自动改变单片尺度。超額部分進 unresolved budget／診斷，不偷給最近乘員。固定 seed 加 stable 事件序；各品質的視覺粒子使用另外的亂數。

碎片用 swept segment 和同一 posed 幾何進行交會，可在殘能足夠時穿過後方薄層。防同板重撞需事件順序、visited crossing、最小進展距離和碰撞上限；不能靠避免穿透所有裝甲的捷徑達到穩定。

## 引信、爆炸與超壓

引信累計實際行程時間，碰撞減速後按更新速度積分，禁止把爆點 clamp 到車內。未啟動、失效、未爆、過穿車外起爆与艙內起爆分別記錄。每份填藥最多起爆一次；零／負／非有限填藥不创造最小裝藥。

爆炸環境分 `ExternalExposure`、`BreachIngress`、`InternalDetonation`，`ArmourShockSpall` 作固體事件。真內爆由所在艙室／封閉面和实际位置判定，不能用包括炮管、履帶及外部模組的整車 AABB。HE 打穿第一片附加板後仍須检查後面的主甲；HESH 只有剝落時不能当作气体入口。HEAT 射流不能自動觸發全車徑向超壓。

逐乘員檢查当时关节／折板后的直接路径与少量已知开口采样；开顶炮塔不将封闭驾驶员升格暴露。内部不同隔舱需要可连通路径。未知舱口／材料缝不作为已验证气体开口。第一版负荷采用版本化无单位工程估计；只在有效自由场范围及已验证TNT当量下输出KB压力／冲量。接触爆炸、近场与车内不能无条件套自由场曲线，也不使用一个统一致死kPa阈值。

固體與化學能分帳，彈殼碎片與壓力響應不能各自无限领取整份化学能；压力／冲量不以错误单位加进动能帐。未知 explosive_type 保留 uncalibrated，不能全部静默称TNT。

## 实际模型几何与权威

精确 hitbox 由实际 emitted float32 render triangles／instances 与同一 accepted pose 生成。包括已提供GLB的解码网格、程序模型及已有内构；原资产不变。BVH／AABB只能筛选，最终不能退回壳体方盒、模块OBB或乘员球。每个表面有稳定装甲／模块／乘员或声明装饰归属；镂空不能补成实体，装饰不冒充主甲。

模型表面不是每处真实钢板厚度，材料／厚度仍从受信任的原有数据取得。内部气体边界与视觉缝隙另有语义，不能用同一裸 triangle-hit 推断真实气密状态。更细的 manifest／pose／BVH／绑定任务由独立 hitbox 设计列出，必须在最终真实路径验收之前完成。履带／轮组姿态依赖 B 的可信动态形状，损毁轮胎依赖 per-wheel 状态。

服务端从可信 catalog、发射事件与统一外弹道取得撞速／距离／方向，不再把合法有限的 client shot.speed／yaw 当物理真值。记录实际发射原点／方向、时间、武器和seed，重播或在可核验轨迹上定位接触。炮弹、碎片、跳弹和近爆使用单个权威事件owner，目标／事件去重；客户端不能上传伤害／质量／能量／碎片／装药来授予自己杀伤。导弹引信与近爆由可信导弹状态接入。

## 回放資料與呈現

使用者於2026-10-11明確說明上傳的 hit-replay V3 是自己的源碼，授權最大限度使用。優先直接移植可用的鏡頭／時間映射／播放控制、著色器／材質、多彈種程序模型與軌跡／碎片繪製程式，依 TankForge 座標、渲染器與資源生命週期接入。可用的 C 取樣／數學也可轉接；演示用固定軌跡、AABB、十二模組與規格化判傷改為實際權威結果。這份授權不是只借鑑畫風；保留原包的 MIT 通知。細節與來源見 `../notes/2026-10-11-hit-replay-v3-intake.md`。

兼容追加 mechanism_revision、impact events 和 fragment provenance；旧报表使用明确adapter。每碰撞记录时间、entry／exit、normal、状态及能量前后；每爆炸记录实际起爆位置、环境、来源／暴露路径。消费者不重新判伤。

R 快照冻结目标；回放将物理时间映射到慢镜头，以真实到达顺序播放弹体、变形、分裂、碎片和起爆。完整弹头在停止后不穿过装甲；碎裂后不继续画完整炮弹，HEAT 只在形成后显示射流，HESH不显示穿板主弹。物理长度作为基础，仅在回放中明确做可读尺寸放大，保持鼻端／起点不移。用颜色和简单标签区分装甲片／弹体片／弹壳片，伤害高亮只在实际到达时发生。

### 连续命中的同视图回放

使用者追加要求：像其描述的战争雷霆行为，连续／同时多次命中时，在同一视图内继续显示多发命中过程，不能每发刷新镜头。对同一 match／target entity／incarnation、兼容模型身份的当前回放追加每发真实 report；保留相机、已播放时钟与当前剖视阶段，第二发不重启 approach、回收旧快照或重置损伤显色。机枪、机关炮、主炮、导弹混合命中遵循同一会话逻辑；每发保有独立 shot／weapon／mechanism ID、弹体、轨迹、穿透结果及来源。相同时刻的事件共同出现，不人为串行延迟。

共享显示会话不合并物理伤害。按各发实际事件时间、accepted pose／geometry revision 与健康前后值累积显示；折板、炮管／轮胎／履带变体也在各自记录时刻转变。使用一个显示目标重建和有界事件／实例池，不每发保存完整GPU模型。若目标运动，各发接触／轨迹与该时刻接受姿态一致；不能把后来直播位置带进先前冻结事件。后到记录按权威时间排序／去重，不回退已播放镜头或再判伤。持续连射只延长有界尾段并回收已完成事件，质量可减少装饰破片而不能让回放不断重启；达到显示预算时明确聚合超额视觉记录，不改 report／计分／致死来源。

其他目标的普通命中进入有界待播项，不拼成同一辆车，也不抢断当前多发过程。玩家阵亡有最高优先级，其当前生命的真实相关 incoming 记录可在同一受害者会话内显示，致死报告与延迟死亡来源始终明确；后到的玩家 outgoing hit 不能覆盖。设计分析的新试射仍可明确开始新分析会话。重生、换头导致模型不兼容、离开战斗及用户主动跳过按原生命周期结束／释放。

验收包含三发同时／连续命中且镜头不重启、持续机关炮／机枪连射、APHE延迟起爆期间另一发进入、混合穿透／停止／跳弹、两目标隔离、不同武器及同车型两实体、目标移动／变体转换、重复／乱序／迟到／旧生命、阵亡优先级及有界资源回收。小窗和全屏在同一帧读取同一组只读事件。

普通战场FX显示有限的命中闪光、金属碎屑、弹托／被帽、局部烟尘和可信爆炸，数量与质量设置不改变伤害。上限和缓存由已有FX体系管理，重复开回放不累积GPU资源。浏览器验收受既有自动审批限制时明确记录尚未视觉验证，不能用CPU通过代替画面证据。
