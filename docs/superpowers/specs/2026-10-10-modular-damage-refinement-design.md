# 模块化损伤改进设计（方案 A 已确认）

基线：`eba77fc3df79dfa78e305f61d5eb13fbc76fe91e`。调研与复现见 `docs/modular-damage-research-2026-10-10.md`。用户于 2026-10-10 确认采用方案 A；按下列范围实施和验收。

## 三种范围

| 方案 | 范围 | 取舍 |
|---|---|---|
| A：细化现有核心（推荐） | 精确模块命中、独立武器故障、健康分级与性能后果、轻伤修复、乘员兼任、统一反馈 | 能解决已确认的错判，同时保留当前游戏节奏和车型数据 |
| B：只修现有错误 | 命中空角、负健康、轻伤无法修复、兼任字段遗漏 | 改动最小，武器依赖与轻伤表现仍较粗 |
| C：进一步模拟舱室 | A 加多火源、燃料泄漏、弹药持续热失控、隔舱传播与安全弹药舱 | 需要逐车补燃料、弹药和隔板信息，并校准参数；实施与验收范围明显扩大 |

推荐 A 作为首轮，C 的数据需求与可借鉴算法已列入研究说明。

## 命中与持久状态

历史车辆转动模块的精确碰撞使用局部盒及逆变换后的射线。粗筛保留包围盒，不能让粗筛包围盒充当真实命中体积。先覆盖现有主炮塔 yaw 及相关模块；当前 Shot 只传主炮塔 yaw，额外炮塔独立角度和炮组俯仰的完整同步属于后续几何扩展，首轮不宣称已解决。

统一损伤入口将模块健康限制在 `[0,max_health]`。零健康部件仍按其几何与既有阻挡机制处理，不因“已损坏”凭空消失；空弹药架继续不产生弹药后效。只记录实际健康变化与一次性状态转换，保证核心、状态小窗和 X 光报告一致。保留注入随机种子和固定处理顺序。

## 功能后果与武器隔离

保留 `Caps` 的兼容整车字段，增加按实际武器实例可查询的故障结果。主炮炮管／炮闩、独立炮塔、车顶机枪、Oplot、导弹发射装置分别查询自己的关键部件与操控岗位；共同的乘员、毁车和正在修复状态仍可限制多个武器。排队到真正发射之间再次检查，以免队列中的武器在模块已毁后开火。

延续现有 `weapon_group` 思路，使用明确的实例关联；现有导弹组件分组保留。旧资料用受约束、可验证的适配映射；多武器歧义不能依赖随意选取最近模块。新依赖需同步服务器识别，客户端的武器状态不能取代服务器校验。普通炮弹、导弹和机枪入口逐个核对。新客户端发送所选武器实例标识，服务器从本车配置核对其依赖、可用状态与弹药；旧请求缺少标识时，只接受可以唯一确定的武器，歧义请求明确拒绝。

健康分级在核心统一派生：健康比例大于 50% 为可用，0–50% 为受损，归零为损毁；可用不等同于被修到满健康。引擎、传动、方向机与高低机的部分损伤影响动力或操纵速率；炮组损伤影响精度或装填，完全损毁禁止相应武器开火。满健康车型保持现有动力、瞄准和装填参数。

首轮性能曲线集中声明，`h` 为限制到 0–1 的健康比例：

| 功能 | 健康大于零时的系数 | 健康归零 |
|---|---|---|
| 引擎动力 | `min(1,0.6+0.8h)` | 0 |
| 传动效率 | `min(1,0.5+h)`，与引擎系数相乘作为驾驶输出 | 0 |
| 炮塔／方向机速率 | `min(1,0.35+1.3h)` | 保留当前手动速率 0.15 |
| 高低机速率 | `min(1,0.5+h)` | 保留当前手动速率 0.3 |
| 本武器炮管／炮闩精度 | 散布倍率 `1+max(0,1-2h)`，取相关部件最差值 | 禁止本武器开火 |
| 有弹的弹药架供弹 | 装填倍率 `1+0.5max(0,1-2h)`，取相关部件最差值；与原乘员倍率相乘 | 保留损伤／火灾流程，不补充弹药 |

导弹发射装置不套用炮管散布曲线，继续遵守现有导弹制导与过载模型。按单调性、端点、修复后的恢复和合理下限验证；这些曲线是首轮游戏标定，不宣称来源游戏或本提案的数值代表历史实测。

## 修复、乘员与提示

短按 F 测距、连续按住 F 三秒准备修复、J 三秒弃车和 K 灭火保留。修复允许当前健康低于既有 60% 战地修复上限的可修部件进入，不要求必须先损毁；不能恢复弹药、复活乘员或重复修到满健康。准备完成时固定本次待修索引，工作量为各目标 `(0.6-h)/0.6` 的和；时间为 `6+4×工作量+2×缺少乘员数` 秒，与旧全毁模块时间尺度一致。

修复中再次受击不加入新的待修模块，也不重置已经开始的时间；到时仅将本次目标恢复到不低于 60%。阵亡、弃车或存活乘员不足两人取消修复。正在起火仍按原火灾规则继续受损，修复不会替代 K 灭火。验证不会免费修复不在目标中的部件。

兼任 `also` 字段完整进入 WASM 核心。乘员失能与接替岗位由核心决定；浏览器、工坊和服务器使用一致定义。现有自动换位继续保留。

状态小窗与命中提示显示受影响的模块及功能，例如“主炮无法开火”“传动受损”“修复恢复到可用状态”，并区分受击、损毁与修复。X 光继续显示实际弹体、轨迹和命中部件，追猎者换头与导弹双发流程保持可用。

## 火灾与弹药边界

首轮保留现有起火、灭火、空架与殉爆流程，检查其状态与事件没有被公共模块改动破坏。多火源、泄漏、持续 cook-off、弹种相关装药风险、隔板及泄压结构属于方案 C；不能凭车型现代程度自动假设存在防殉爆舱，也不凭视觉模型推断未标注的隔板。

## 结构与兼容

公共类型和基础模块语义由 `crates/damage` 拥有；历史车辆的持久状态、功能能力和修复由 `crates/combat` 拥有；工坊试射检查 `crates/design`。浏览器适配器只传递数据和调用核心，HUD 只显示结果。服务器继续拥有联机损伤、死亡与修复结果。

可选新字段使用明确默认值，不破坏已有资料导入、工坊导出和状态序列化。模块 schema 与运行时类型一致。保留原车辆装甲、武器数值、GLB 与既有换头配置，来源参考不带入车型标定和美术资源。

## 验收

先将已确认的错误写成失败回归，再实施：

- 0°、45°、90° 等姿态的真实盒命中／空角擦过；正常模块遮挡不退化。
- 过量伤害后健康保持零，重复命中不重复发布损毁事件，报告与持久状态一致。
- 主炮损毁不关闭健康的独立 Oplot／机枪／导弹；对应独立部件损毁能禁止其自身开火；双发导弹消费与装填继续成立。
- 同一车辆满健康、轻伤、重伤、损毁与修后能力保持单调；满健康性能与基线一致。
- 部分损伤可以修复，空架／弹药不被修复补充；F/J 三秒边界、移动、聊天和失焦取消保留。
- 兼任乘员死亡与换位、历史车辆／工坊／服务器的一致性；追猎者换头、状态小窗与 X 光回放回归。
- 定向 Rust／WASM／网页测试、服务器相关测试、完整网页回归、实际 WASM／网页重建及资料差异审计；禁止旧核心回退。

本地浏览器访问限制继续遵守，使用实际 WASM、CPU 几何、事件／DOM 属性、构建与回归验收。完成后推送公开仓库，并同步标准页面、原有别名与新的模块损伤版本页面。
